# Development

Use 64-bit Python 3.12–3.14. This workstation uses Python 3.14.3 in `.venv`.
Python 3.15 is not the selected dependency target. No system drivers were changed.

```powershell
./scripts/setup_dev.ps1 -Python 'C:/path/to/python.exe' -DownloadFFmpeg
./scripts/run.ps1
```

Setup uses the pinned Python lock file and an explicit opt-in FFmpeg download.
Alternatively provide existing executables via `ASTRA_FFMPEG` and `ASTRA_FFPROBE`.
No activation is required when invoking `.venv/Scripts/python.exe` directly.

```powershell
./.venv/Scripts/python.exe -m scripts.generate_fixtures
./.venv/Scripts/python.exe -m ruff check app scripts tests
./.venv/Scripts/python.exe -m ruff format --check app scripts tests
./.venv/Scripts/python.exe -m pytest -q
```

Desktop integration tests require an unlocked interactive Windows session and multimedia
devices. They check decoded frame changes, not just a PlayingState flag. Sample media is
generated by FFmpeg; no user media or downloaded copyrighted footage is required.
Test output is under the standard pytest temporary directory unless `--basetemp` is supplied.

Use `python -m app.main "C:/path/to/video.mp4"` to import at startup.
Pass a single `.astra` or `.astra.bak` path to open a project instead. With no arguments,
startup offers the most recent recovery copy if one exists. `ASTRA_DATA_DIR` overrides the
recovery directory for isolated tests. Tests substitute confirmation answers only inside
their fixtures and use generated media; application confirmation behavior is unchanged.

Phase 2 regression report: `python -m pytest -q --junitxml=artifacts/phase2-tests.xml`.
Phase 3 regression report: `python -m pytest -vv -o faulthandler_timeout=30 --junitxml=artifacts/phase3-tests.xml`.
Render integration tests invoke real FFmpeg/FFprobe and inspect decoded RGB frames and PCM
audio. Export desktop tests also verify cancellation during a running encode and playback
of the resulting file. No new Python dependencies were required for Phase 3.
Run GUI tests in the interactive desktop session. The restricted execution runner on this
workstation has terminated inside native Qt/Windows initialization; a model-only test run
does not replace the interactive playback suite.
Build/install/release automation belongs to Phase 8 and is not implemented yet.

Phase 4 optional AI setup: `./scripts/setup_ai.ps1`, then explicitly download a model through
the subtitle panel. The AI lock is separate from the editor lock. Generate original spoken
test media with `./scripts/generate_speech.ps1` (installed Windows SAPI voice).
Run `python -m pytest -vv -o faulthandler_timeout=30 --junitxml=artifacts/phase4-tests.xml`.
Real inference cases skip only when the optional model/speech fixture is absent; on this
workstation all 66 tests ran and passed. `ASTRA_MODELS_DIR` and `ASTRA_AI_PYTHON` support
isolated configuration. See docs/TRANSCRIPTION.md for compatible versions and GPU limitations.

Phase 5 uses the existing FFmpeg binary; no editor or AI dependency changes are required.
Run `python -m pytest -vv -o faulthandler_timeout=30 --junitxml=artifacts/phase5-tests.xml`.
All 75 tests passed on this workstation. Audio tests decode PCM to verify processing and mix
behavior, measure loudness, validate waveform caching and exercise real Qt preview/export jobs.
See docs/AUDIO_STUDIO.md for processing semantics and current limitations.

Phase 6 uses Rubber Band inside the existing FFmpeg build; no new Python packages are needed.
Run `python -m pytest -vv -o faulthandler_timeout=30 --junitxml=artifacts/phase6-tests.xml`.
The full suite passed 85 tests; three Audio Studio desktop tests also passed after the native
layout fix. Voice capability detection runs inside the render worker, and unavailable builds
fail with a visible error. See docs/VOICE_TRANSFORMATION.md for optional model evaluation.
